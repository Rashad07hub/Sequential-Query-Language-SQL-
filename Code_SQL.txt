Here’s a structured set of common Data Analyst problem-solving questions using SQL, moving from basic → intermediate → advanced, with realistic examples and solutions (PostgreSQL style, but mostly transferable).
________________________________________
1. BASIC LEVEL
1. Retrieve all data
Problem: Get all records from a table.
SELECT * FROM beneficiaries;
________________________________________
2. Filter data
Problem: Get beneficiaries from Dhaka district.
SELECT *
FROM beneficiaries
WHERE district = 'Dhaka';
________________________________________
3. Sort data
Problem: Show households sorted by size (largest first).
SELECT beneficiary_id, household_size
FROM beneficiaries
ORDER BY household_size DESC;
________________________________________
4. Count records
Problem: Total number of beneficiaries.
SELECT COUNT(*) AS total_beneficiaries
FROM beneficiaries;
________________________________________
5. Remove duplicates
Problem: Get unique districts.
SELECT DISTINCT district
FROM beneficiaries;
________________________________________
2. INTERMEDIATE LEVEL
6. Aggregation with GROUP BY
Problem: Total beneficiaries per district.
SELECT district, COUNT(*) AS total
FROM beneficiaries
GROUP BY district;
________________________________________
7. HAVING (filter aggregated data)
Problem: Districts with more than 100 beneficiaries.
SELECT district, COUNT(*) AS total
FROM beneficiaries
GROUP BY district
HAVING COUNT(*) > 100;
________________________________________
8. JOIN tables
Problem: Get beneficiary info with distribution details.
SELECT b.beneficiary_id, b.district, d.distribution_date, d.amount
FROM beneficiaries b
INNER JOIN distributions d
ON b.beneficiary_id = d.beneficiary_id;
________________________________________
9. LEFT JOIN (missing data analysis)
Problem: Find beneficiaries who never received aid.
SELECT b.beneficiary_id
FROM beneficiaries b
LEFT JOIN distributions d
ON b.beneficiary_id = d.beneficiary_id
WHERE d.beneficiary_id IS NULL;
________________________________________
10. CASE WHEN (categorization)
Problem: Classify households.
SELECT beneficiary_id,
       household_size,
       CASE 
           WHEN household_size >= 6 THEN 'Large'
           WHEN household_size BETWEEN 3 AND 5 THEN 'Medium'
           ELSE 'Small'
       END AS category
FROM beneficiaries;
________________________________________
3. ADVANCED LEVEL
11. Window Functions (Ranking)
Problem: Rank beneficiaries by household size within each district.
SELECT beneficiary_id,
       district,
       household_size,
       ROW_NUMBER() OVER (PARTITION BY district ORDER BY household_size DESC) AS rank
FROM beneficiaries;
________________________________________
12. Running Total
Problem: Cumulative distribution amount over time.
SELECT distribution_date,
       SUM(amount) AS daily_total,
       SUM(SUM(amount)) OVER (ORDER BY distribution_date) AS running_total
FROM distributions
GROUP BY distribution_date;
________________________________________
13. Subquery
Problem: Find beneficiaries with above-average household size.
SELECT *
FROM beneficiaries
WHERE household_size > (
    SELECT AVG(household_size)
    FROM beneficiaries
);
________________________________________
14. Common Table Expression (CTE)
Problem: Top 3 largest households per district.
WITH ranked AS (
    SELECT beneficiary_id,
           district,
           household_size,
           ROW_NUMBER() OVER (PARTITION BY district ORDER BY household_size DESC) AS rnk
    FROM beneficiaries
)
SELECT *
FROM ranked
WHERE rnk <= 3;
________________________________________
15. Pivot-style aggregation
Problem: Monthly distribution totals.
SELECT 
    EXTRACT(MONTH FROM distribution_date) AS month,
    SUM(amount) AS total_distribution
FROM distributions
GROUP BY month
ORDER BY month;
________________________________________
16. Detect duplicates
Problem: Find duplicate beneficiary records.
SELECT beneficiary_id, COUNT(*)
FROM beneficiaries
GROUP BY beneficiary_id
HAVING COUNT(*) > 1;
________________________________________
17. Gap detection (missing dates)
Problem: Find missing distribution dates.
SELECT d1.distribution_date + INTERVAL '1 day' AS missing_date
FROM distributions d1
LEFT JOIN distributions d2
ON d1.distribution_date + INTERVAL '1 day' = d2.distribution_date
WHERE d2.distribution_date IS NULL;
________________________________________
18. Advanced JOIN (Self Join)
Problem: Compare distributions day-to-day.
SELECT 
    d1.distribution_date,
    d1.amount AS today,
    d2.amount AS previous_day
FROM distributions d1
LEFT JOIN distributions d2
ON d1.distribution_date = d2.distribution_date + INTERVAL '1 day';
________________________________________
4. REAL-WORLD SCENARIO QUESTIONS (VERY IMPORTANT)
These are commonly asked in interviews 👇
________________________________________
19. Top N per group
SELECT *
FROM (
    SELECT district,
           beneficiary_id,
           amount,
           RANK() OVER (PARTITION BY district ORDER BY amount DESC) AS rnk
    FROM distributions
) t
WHERE rnk <= 3;
________________________________________
20. Retention / Repeat beneficiaries
SELECT beneficiary_id
FROM distributions
GROUP BY beneficiary_id
HAVING COUNT(*) > 1;
________________________________________
21. Percentage contribution
SELECT district,
       SUM(amount) AS total,
       ROUND(100.0 * SUM(amount) / SUM(SUM(amount)) OVER (), 2) AS percentage
FROM distributions d
JOIN beneficiaries b ON d.beneficiary_id = b.beneficiary_id
GROUP BY district;
________________________________________
22. First & last transaction
SELECT beneficiary_id,
       MIN(distribution_date) AS first_received,
       MAX(distribution_date) AS last_received
FROM distributions
GROUP BY beneficiary_id;

After you create a table (or result) using an INNER JOIN, how you “use” it depends on whether you saved it or not.
✅ 1. If you just used INNER JOIN in a query (not saved)
SELECT b.Beneficiary_ID, b.Name, d.Food_Ration
FROM beneficiaries b
INNER JOIN distributions d
ON b.Beneficiary_ID = d.Beneficiary_ID;
This result is temporary—you can’t reuse it directly later.
To use it again, you have two main options:
🔹 Option A: Use a subquery
SELECT *
FROM (
    SELECT b.Beneficiary_ID, b.Name, d.Food_Ration
    FROM beneficiaries b
    INNER JOIN distributions d
   ON b.Beneficiary_ID = d.Beneficiary_ID
) AS joined_table
WHERE Food_Ration> 30;
🔹 Option B: Use a CTE (Common Table Expression)
WITH joined_table AS (
    SELECT b.Beneficiary_ID, b.Name, d.Food_Ration
    FROM beneficiaries b
    INNER JOIN distributions d
   ON b.Beneficiary_ID = d.Beneficiary_ID
)
SELECT *
FROM joined_table
WHERE Food_Ration> 30;
👉 This is the cleanest and most common approach.
________________________________________
✅ 2. If you created a new table using INNER JOIN
If you did something like:
CREATE TABLE beneficiary AS
    SELECT b.Beneficiary_ID, b.Name, d.Food_Ration
    FROM beneficiaries b
    INNER JOIN distributions d
   ON b.Beneficiary_ID = d.Beneficiary_ID;
Now it’s a permanent table, and you can use it like any other table:
SELECT * FROM beneficiary;
SELECT name
FROM beneficiary
WHERE food_ration> 30;
________________________________________
✅ 3. If you created a VIEW (recommended for reuse)
CREATE VIEW employee_salary_view AS
SELECT a.id, a.name, b.salary
FROM employees a
INNER JOIN salaries b
ON a.id = b.emp_id;
Now use it like a table:
SELECT * FROM employee_salary_view;
________________________________________
🔥 Best Practice (Important)
•	Use CTE (WITH) → for temporary, readable queries
•	Use VIEW → when you need reuse without storing data
•	Use TABLE → when you need to store results physically

/* Different SQL Operators:::    = , <, >, >=, <=, <>, !=, BETWEEN, ORDER BY, IN, NOT IN, LIKE, ALIASE, DISTINCT, LIMIT, CASE:
Comparison Operators: =, <>, != , >, <, >=, <=
Arithmetic Operators: +, -, *, /, %
Logical Operators: AND, OR, NOT, IN, BETWEEN, LIKE etc.    */

--- Basic queries
SELECT * FROM STUDENTS;   -- Fetch all columns and all records (rows) from table.
SELECT ID, FIRST_NAME FROM STUDENTS; -- Fetch only ID and FIRST_NAME columns from students table.
---- Comparison Operators
SELECT * FROM SUBJECTS 
WHERE SUBJECT_NAME = 'Mathematics'; -- Fetch all records where subject name is Mathematics.
SELECT * FROM SUBJECTS 
WHERE SUBJECT_NAME <> 'Mathematics'; -- Fetch all records where subject name is not Mathematics.
SELECT * FROM SUBJECTS 
WHERE SUBJECT_NAME != 'Mathematics'; -- same as above. Both "<>" and "!=" are NOT EQUAL TO operator in SQL.
SELECT * FROM STAFF_SALARY 
WHERE SALARY > 10000; -- All records where salary is greater than 10000.
SELECT * FROM STAFF_SALARY 
WHERE SALARY < 10000; -- All records where salary is less than 10000.
SELECT * FROM STAFF_SALARY 
WHERE SALARY < 10000 ORDER BY SALARY; -- All records where salary is less than 10000 and the output is sorted in ascending order of salary.
SELECT * FROM STAFF_SALARY 
WHERE SALARY < 10000 ORDER BY SALARY DESC; -- All records where salary is less than 10000 and the output is sorted in descending order of salary.
SELECT * FROM STAFF_SALARY WHERE SALARY >= 10000; -- All records where salary is greater than or equal to 10000.
SELECT * FROM STAFF_SALARY WHERE SALARY <= 10000; -- All records where salary is less than or equal to 10000.

--- Logical Operators
SELECT * FROM STAFF_SALARY 
WHERE SALARY BETWEEN 5000 AND 10000; -- Fetch all records where salary is between 5000 and 10000.
SELECT * FROM SUBJECTS 
WHERE SUBJECT_NAME IN ('Mathematics', 'Science', 'Arts'); -- All records where subjects is either Mathematics, Science or Arts.
SELECT * FROM SUBJECTS 
WHERE SUBJECT_NAME NOT IN ('Mathematics', 'Science', 'Arts'); -- All records where subjects is not Mathematics, Science or Arts.
SELECT * FROM SUBJECTS 
WHERE SUBJECT_NAME LIKE 'Computer%'; -- Fetch records where subject name has Computer as prefixed. % matches all characters.
SELECT * FROM SUBJECTS 
WHERE SUBJECT_NAME NOT LIKE 'Computer%'; -- Fetch records where subject name does not have Computer as prefixed. % matches all characters.
SELECT * FROM STAFF 
WHERE AGE > 50 AND GENDER = 'F'; -- Fetch records where staff is female and is over 50 years of age. AND operator fetches result only if the condition mentioned both on left side and right side of AND operator holds true. In OR operator, atleast any one of the conditions needs to hold true to fetch result.
SELECT * FROM STAFF 
WHERE FIRST_NAME LIKE 'A%' AND LAST_NAME LIKE 'S%'; -- Fetch record where first name of staff starts with "A" AND last name starts with "S".
SELECT * FROM STAFF 
WHERE FIRST_NAME LIKE 'A%' OR LAST_NAME LIKE 'S%'; -- Fetch record where first name of staff starts with "A" OR last name starts with "S". Meaning either the first name or the last name condition needs to match for query to return data.
SELECT * FROM STAFF 
WHERE (FIRST_NAME LIKE 'A%' OR LAST_NAME LIKE 'S%') AND AGE > 50; -- Fetch record where staff is over 50 years of age AND has his first name starting with "A" OR his last name starting with "S".

---- Arithmetic Operators
SELECT (5+2) AS ADDITION;   -- Sum of two numbers. PostgreSQL does not need FROM clause to execute such queries.
SELECT (5-2) AS SUBTRACT;   -- Oracle & MySQL equivalent query would be -->  select (5+2) as Addition FROM DUAL; --> Where dual is a dummy table.
SELECT (5*2) AS MULTIPLY;
SELECT (5/2) AS DIVIDE;   -- Divides 2 numbers and returns whole number.
SELECT (5%2) AS MODULUS;  -- Divides 2 numbers and returns the remainder

SELECT STAFF_TYPE FROM STAFF ; -- Returns lot of duplicate data.
SELECT DISTINCT STAFF_TYPE FROM STAFF ; -- Returns unique values only.
SELECT STAFF_TYPE FROM STAFF LIMIT 5; -- Fetches only the first 5 records from the result.
---- CASE statement:  (IF 1 then print True ; IF 0 then print FALSE ; ELSE print -1)
SELECT STAFF_ID, SALARY
, CASE WHEN SALARY >= 10000 THEN 'High Salary'
       WHEN SALARY BETWEEN 5000 AND 10000 THEN 'Average Salary'
       WHEN SALARY < 5000 THEN 'Too Low'
  END AS RANGE
FROM STAFF_SALARY
ORDER BY 2 DESC;

---- TO_CHAR / TO_DATE:
SELECT * FROM STUDENTS WHERE TO_CHAR(DOB,'YYYY') = '2014';
SELECT * FROM STUDENTS WHERE DOB = TO_DATE('13-JAN-2014','DD-MON-YYYY');
